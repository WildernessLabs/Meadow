The AOT process will convert artifacts of the build process and libraries (i.e. `.exe` and `.dll` files) into native code `.so` files that mono can invoke at runtime. This project provides three such mechanisms:
1. Compiling the JITted code. A JIT compiler has been implemented for the thumb2 architecture. This can then be used to produce AOT modules (shared objects).
2. Using mono's LLVM support to compile, assemble, link, and strip the shared objects.
3. Using mono's LLVMONLY support compile to bitcode which is then post-processed using the LLVM tools `opt`, `llc`, and `clang` along with the GNU tools `ld` and `strip` to create the shared objects.

## <a name="overview">Process Overview</a>
1. Building the applications artifacts using whatever tools the application programmer chooses.
2. Running those artifacts through `monolinker` to produce the minimal set of system `.dll` files required to execute the application. See [Sample AOT generation script](#genaot) to show how this may be done.
3. The output of the mono linker are also put through the AOT process that results in `.so` files. See [Sample AOT generation script](#genaot) to show how this may be done.
4. Mono will dynamically load the `.so` files at runtime to execute the application.

## <a name="dynloader">Dynamic Loader</a>
NuttX has been enhanced to support the loading of dynamic shared objects (ET_DYN). This involves:
* Reading the shared object
* Analyzing the program headers to determine locations and sizes
* Loading in the text and data sections
* Performing any relocations
* Resolving undefined symbols by referencing the global entry point table built as part of the NuttX executable
* Supporting dlsym() calls to return the addresses of symbols within the shared object 

## <a name="bit">JIT</a>
Those instructions in the thumb2 instruction set required to build and run applications have been implemented in mono. This means applications can be run in JIT mode, or put through the AOT process to generate shared objects.

## <a name="llvmonly">LLVMONLY</a>
Using the LLVM capability of mono, AOT shared objects are able to be generated by specifying the `--aot=llvmonly,asmonly` option on the mono command line.
From [Mono LLVMONLY/Bitcode description](https://www.mono-project.com/docs/advanced/runtime/docs/BITCODE/)

_Bitcode imposes the following major restrictions:_
*	_No inline assembly/machine code_
*	_Compilation using stock clang_
_To enable the runtime to operate in this environment, a new execution mode `llvmonly` was implemented._

_In this mode:_
*	_Everything is compiled to llvm bitcode, then compiled to native code using clang_
*	_No trampolines, etc. are used_

### Components
1. `monolinker` – to create DLLs with only the code required for the application
2. `mono` – to perform the AOT process which creates the bitcode. The mono cross-compiler is built using the `build-mono-aot-jit.sh` script
3. LLVM 11 or higher – for `clang` which converts bitcode to thumb2 object code	
4. `arm-none-eabi-binutils-cs`:	
	* `arm-none-eabi-ld` – to link object code into self-container shared object
  * `arm-none-eabi-strip` – to strip unnecessary symbols from shared object
5. `arm-none-eabi-gcc-cs`- for `libsupc++.a`

#### <a name="buildllvm">Building LLVM</a>
This mode uses both the internal LLVM support of mono to generate the bitcode and an external `clang` command to produce the artifacts.

LLVM 11.0.1 was used as the code base for `clang`. This script builds the required components. LLVM requires gcc version 5.3.x or above. I chose to use gcc 9.3.1 which is available in the RHEL developer toolset (`devtoolset-9-gcc-c++`).

```
#!/bin/sh
. /opt/rh/devtoolset-9/enable
cmake -DLLVM_ENABLE_PROJECTS="compiler-rt;clang " \
        -DLLVM_TARGETS_TO_BUILD="ARM;X86" \
        ../llvm
nohup make >make.log 2>&1 &
exit
```

### Limitations
1. Compilation times are an order of magnitude greater than for any of the other methods. It takes close to 50 minutes to build the benchmark program.
2. Certain methods are not able to be compiled but will be JITted at runtime. For example,
	`LLVM failed for 'NetworkStream.Read': non-finally/catch/fault clause.`
		
## <a name="genaot">Script to Generate AOT artifacts</a>
The `genAot.sh` script is part of the [AOT Support Library](#aotsupport) repository.
	
```
[000] #!/bin/bash
[001]
[002]
[003] #
[004] # Use monolinker to produce a subset of the DLLs needed at runtime
[005] #
[006] function build_dll()
[007] {
[008] 	  export PATH=/opt/mono/bin:${OLD_PATH}
[009] 	  RC=0
[010] 	  ARGS=`ls input/*.{exe,dll} | awk '{print "-a "$1" "}'`
[011] 	  monolinker -l all -c link -o output ${ARGS[@]}
[012] 	  RC=$?
[013] 	  export PATH=${OLD_PATH}
[014] 	  return ${RC}
[015] }
[016]
[017] #
[018] # Build the AOT shared objects in LLVM mode
[019] #
[020] function llvm_build_so()
[021] {
[022] 	  FN=`basename $1`
[023] 	  echo "Compiling ${FN}"
[024] 	  export PATH=/opt/mono.jit/bin:${OLD_PATH}
[025] 	  export MONO_PATH=${PWD}/output
[026] 	  if [ ${KEEP} -eq 1 ]; then
[027] 		  KEEPOPT=",keep-temps"
[028] 	  else
[029] 		  KEEPOPT=""
[030] 	  fi
[031] 	  MONO_LDFLAGS="${LDFLAGS} -Map=output/${FN}.map"
[032] 	  mono --aot="llvm,${LLVMOPTS},ld-flags=${MONO_LDFLAGS}${KEEPOPT}" output/${FN}
[033] 	  if [ $? -ne 0 ]; then
[034] 		  echo "Error compiling ${FN}" >&2
[035] 		  exit 1
[036] 	  fi
[037] 	  export MONO_PATH=""
[038] 	  export PATH=${OLD_PATH}
[039] }
[040]
[041] #
[042] # Build the AOT shared objects in JIT mode
[043] #
[044] function jit_build_so()
[045] {
[046]   	FN=`basename $1`
[047] 	  echo "Compiling ${FN}"
[048] 	  export PATH=/opt/mono.jit/bin:${OLD_PATH}
[049] 	  export MONO_PATH=${PWD}/output
[050] 	  if [ ${KEEP} -eq 1 ]; then
[051] 		  KEEPOPT="keep-temps"
[052] 	  else
[053] 		  KEEPOPT=""
[054] 	  fi
[055] 	  mono --aot="${KEEPOPT}" output/${FN}
[056] 	  if [ $? -ne 0 ]; then
[057] 		  echo "Error compiling ${FN}" >&2
[058] 		  exit 1
[059] 	  fi
[060] 	  export MONO_PATH=""
[061] 	  export PATH=${OLD_PATH}
[062] }
[063]
[064] #
[065] # Build the AOT shared objects in JIT mode
[066] #
[067] function llvmonly_build_so()
[068] {
[069] 	  FN=`basename $1`
[070] 	  echo "Compiling ${FN}"
[071] 	  export PATH=/opt/mono.jit/bin:/opt/llvm/bin:${OLD_PATH}
[072] 	  export MONO_PATH=${PWD}/output
[073] 	  mono --aot="llvmonly,asmonly,interp,llvm-outfile=output/${FN}.bc,llvmllc=-exception-model=dwarf" output/${FN}
[074] 	  if [ -f output/${FN}.bc ]; then
[075] 		  echo "Clanging ${FN}"
[076] 		  clang   -fpic -O1 -fno-optimize-sibling-calls -Ono-override-module --target=thumb2-none-eabi \
[077] 		    	-mcpu=cortex-m7 -mfloat-abi=hard -mfpu=fpv5-d16 -c -o output/${FN}.o output/${FN}.bc
[078] 		  if [ -f output/${FN}.o ]; then
[079] 			  if [ ${KEEP} -eq 0 ];then
[080] 				  rm -f output/${FN}.bc
[081] 			  fi
[082] 			  echo "Linking ${FN}"
[083] 			  arm-none-eabi-ld -shared -G -Bsymbolic -z max-page-size=1024 \
[084] 				  -E \
[085] 				  -z common-page-size=1024 --no-dynamic-linker -pie \
[086] 				  --strip-debug -no-enum-size-warning \
[087] 				  --export-dynamic-symbol=mono_aot_* \
[088] 				  -z combreloc \
[089] 				  -o output/${FN}.so output/${FN}.o \
[090] 				  --entry mono_aot_file_info \
[091] 				  --start-group \
[092] 				    -L${PWD} -lbuiltin \
[093] 				    -L${ARM_LIB} -lsupc++ \
[094] 				    -L${ARM_GCCLIB} -lgcc \
[095] 				  --end-group -Map=output/${FN}.map
[096] 			  RC=$?
[097] 			  if [ -f output/${FN}.so ]; then
[098] 				  if [ ${KEEP} -eq 0 ];then
[099] 					  rm -f output/${FN}.o
[100] 				  fi
[101] 				  arm-none-eabi-strip --wildcard --strip-symbol=\$a.* \
[102] 					  --strip-symbol=\$d.* --strip-symbol=\$t.* \
[103] 					  --strip-symbol=\$a --strip-symbol=\$d --strip-symbol=\$t output/${FN}.so
[104] 			  else
[105] 				  echo "Error linking ${FN} - rc: ${RC}" >&2
[106] 				  exit 3
[107] 			  fi
[108] 		  else
[109] 			  echo "Error clanging ${FN}" >&2
[110] 			  exit 2
[111] 		  fi
[112] 	  else
[113] 		  echo "Error compiling ${FN}" >&2
[114] 		  exit 1
[115]   	fi
[116] 	  export MONO_PATH=""
[117] 	  export PATH=${OLD_PATH}
[118] }
[119]
[120] #
[121] # Call the appropriate AOT build mode
[122] #
[123] function build_so()
[124] {
[125] 	  case ${1} in
[126] 	  llvm)
[127] 		  llvm_build_so $2
[128] 		  ;;
[129] 	  jit)
[130] 		  jit_build_so $2
[131] 		  ;;
[132]   	llvmonly)
[133] 		  llvmonly_build_so $2
[134] 		  ;;
[135] 	  esac
[136] }
[137]
[138] #
[139] # Display usage information and any (optional) error message
[140] #
[141] usage()
[142] {
[143] 	  if [ -n $1 ]; then
[144] 		  echo $1 >&2
[145] 		  echo >&2
[146] 	  fi
[147] 	  echo "genAOT -t <type> -k -o -s" >&2
[148] 	  echo >&2
[149] 	  echo "where:" >&2
[150] 	  echo "   -t <type>   Type of AOT: 'llvm', 'jit', 'llvmonly'" >&2
[151] 	  echo "   -k          Keep any intermediate files" >&2
[152] 	  echo "   -s          Skip monolinker step" >&2
[153] 	  exit 1
[154] }
[155]
[156] #
[157] # Where to find the thumb2 library archives
[158] #
[159] export ARM_LIB=/usr/arm-none-eabi/lib/thumb/v7e-m/fpv5/hard
[160]
[161] OLD_PATH=${PATH}
[162] KEEP=0
[163] SKIP=0
[164] TYPE=""
[165] while getopts "t:ks" opt
[166] do
[167] 	  case "${opt}" in
[168] 	  k)
[169] 		  KEEP=1;
[170] 		  ;;
[171] 	  s)
[172] 		  SKIP=1;
[173] 		  ;;
[174] 	  t)
[175] 		  TYPE=${OPTARG}
[176] 		  ;;
[177] 	  esac
[178] done
[179] shift $(( OPTIND - 1 ))
[180]
[181] #
[182] # Set any AOT mode-specific flags
[183] #
[184] case ${TYPE} in
[185]   llvm)
[186] 	    LDFLAGS="-E -z max-page-size=1024 -z common-page-size=1024 --no-dynamic-linker -pie --strip-debug -no-enum-size-warning --export-dynamic-symbol=mono_aot_* -z combreloc --start-group -L${PWD} -lbuiltin -L${ARM_LIB_1} -lsupc++_nano -L${ARM_LIB_2} -lgcc  --end-group --long-plt --entry mono_aot_file_info"
[187] 	    LLVMOPTS="llvmopts=-mtriple=arm-none-eabi-thumb,llvmopts=-float-abi=hard,llvmopts=-mattr=+vfp4,llvmopts=-mattr=+armv7e-m,llvmllc=-mattr=+armv7e-m"
[188] 	    ;;
[189]   llvmonly)
[190] 	    export ARM_GCCLIB="/usr/lib/gcc/arm-none-eabi/7.1.0/thumb/v7e-m/fpv5/hard"
[191] 	    ;;
[192]   jit)
[193] 	    ;;
[194]   *)
[195] 	    usage "Unknown AOT method: ${TYPE} - valid methods: llvm, jit, or llvmonly"
[196] 	    exit 1
[197] 	  ;;
[198] esac
[199]
[200] #
[201] # If we've already run the monolinker then we can ask to skip this step
[202] #
[203] if [ ${SKIP} -eq 1 ]; then
[204]   	cp input/App.exe output
[205] 	  SOS=`ls output/*.{exe,dll}`
[206] 	  for so in ${SOS}
[207] 	  do
[208] 		  build_so ${TYPE} ${so}
[209] 	  done
[210] else
[211] 	  rm -rf output
[212] 	  mkdir output
[213] 	  build_dll

[215] 	  #
[216] 	  # For all the artifacts produced by the linker - AOT them
[217]   	#
[218] 	  if [ $? -eq 0 ]; then
[219] 		  #
[220] 		  # We do mscorlib last as it takes the longest - especially in LLVMONLY mode
[221] 		  SOS=`ls output/*.{exe,dll} | grep -v mscorlib`
[222] 		  for so in ${SOS}
[223] 		  do
[224] 			  build_so ${TYPE} ${so}
[225] 		  done
[226] 		  build_so output/mscorlib.dll
[227] 	  fi
[228] fi
```

## <a name="openq">Open Questions</a>
To use AOT there are some issues that need to be addressed.

### Packaging
How to package for use by end-users: there are a number of components for this process that are required to perform the building of the artifacts. The mono used to AOT compile the code must be at the same level of the mono used to run the application. The mono AOT runtime will check these levels.

### Support Library
Both modes of LLVM require a library of support routines (shown in the [sample script](#genaot) as `libbuiltin.a`. This would need shipping to developers who want to exploit these AOT modes. In addition, the source and build of this library needs to controlled by current Wilderness git practices. Currently, this library resides in the [`aot-support`](#aotsupport) tree of the main Meadow github repository.

### External LLVM
For the LLVMONLY mode of AOT an external build of clang is required. See [Building LLVM](#buildllvm).

## <a name="xcomp">Building the Cross Compiler</a>
Use the `build-mono-aot-jit.sh` to configure mono to build a cross-compiler targeting the thumb2 platform. This script will build mono twice:
1. The first time to build the libraries required by the cross-compiler
2. The second time to build cross-compiler
It is necessary to build the libraries as the corlib version is checked both at build time (by the cross-compiler) and run-time (by the mono running on the Meadow board(s)). Therefore, we need to ensure all the components originate from the same source.
The cross-compiler is built as an i686 32-bit executable due to the way pointers in mono's internal control blocks must match the size of the pointers on the target platform. 
Depending on the size of the machine you are building the cross-compiler on, you may need to export the following flag when running make to reduce the memory requirements:
`export MAKEFLAGS="-j 2"`

The output from this procedure will be a tar ball: `/tmp/mono.jit.tar.xz`.

## <a name="aotsupport">AOT Support Library</a>
When building AOT modules in either LLVM or LLVMONLY mode there is a requirement to supply several APIs usually supplied by the compiler runtime.
For NuttX we need to supply these ourselves. The `aot-support` repository contains the source for the AOT support routines. A simple `Makefile` is used to build the `libbuiltin.a` artifact.
